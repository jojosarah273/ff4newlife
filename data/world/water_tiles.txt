# Rendering note: in the underground the band's colours come from the palette
# animation (UpdateLavaPal @c4cd), so the tiles look dull with the static
# palette - do not try to identify lava by colour, use the report.

# --- mechanism (field/field.asm), found after the reports
# WaitFrame @914b calls, every frame:
#   overworld  ($1700 == 0): UpdateWaterAnim @8fa1 + TfrWaterGfx @8e67
#   underground($1700 == 1): UpdateLavaAnim  @8ee3 + TfrLavaGfx @8f34
#                            + UpdateLavaPal @c4cd
#   both: TfrBGAnimGfx, UpdateWhalePal, UpdateBabilPal
#
# UpdateWaterAnim is NOT a 4-phase graphics upload (that is the field maps,
# VRAM $120..$12F).  It is a TILEMAP ROTATION: every frame it rotates an
# 8-tile run of the world tilemap by one position, walking a 16-step cycle:
#   WaterShiftX @90aa: 00 88 10 98 20 a8 30 b8 80 08 90 18 a0 28 b0 38
#   WaterShiftY @909a: 00 41 02 43 04 45 06 47 40 01 42 03 44 05 46 07
# horizontal pass uses ($7c >> 1) & 15 and is skipped on odd $7c;
# vertical pass uses $7c & 15 every frame.  UpdateLavaAnim returns early on
# odd $7c, so lava rotates every second frame.
# Emulator agrees: ~15 tilemap entries change per frame while the wave runs,
# and no cell changed more than once in 120 frames of the intro flyover.
